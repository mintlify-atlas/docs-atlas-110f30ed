Spotify ships a remote configuration system — sometimes called "remote config" or "experiments" — that gates features behind internal boolean flags. The client fetches its flag assignments from Spotify's servers at startup, which means Spotify can turn features on or off for any user at any time. SpotX intercepts this resolver and injects its own `enable`, `disable`, and `custom` arrays before the client reads them, giving you a stable, predictable feature set regardless of what Spotify's servers push.

---

## The `ForcedExp` Patch Mechanism

SpotX patches the Spotify JavaScript bundle to inject the following logic immediately after the remote config resolver is initialized:

```javascript
const experiments = { enable: [], disable: [], custom: [] };

const setExpValue = (v, e, val) =>
  v && (v.set ? v.set(e, val) : v[e] && (v[e].value = val));

const config =
  $2.getRemoteConfigResolver?.() || $2.getRemoteConfiguration?.();

if (config) {
  (values => {
    for (const type in experiments)
      experiments[type].forEach(exp =>
        setExpValue(
          values,
          type === 'custom' ? exp.name : exp,
          type === 'custom' ? exp.value : type === 'enable'
        )
      );
    (window.Spotx ?? {}).RemoteExp = values;
  })(config.values || config.activeProperties);
}
```

The `enable`, `disable`, and `custom` arrays are populated by SpotX at patch time based on your chosen flags and the Spotify version detected. The final resolved state is also written to `window.Spotx.RemoteExp` so you can inspect it in DevTools.

<Note>
  The exact set of feature flags injected varies by Spotify version. SpotX reads each flag's `fr` (from) and `to` (to) version bounds from `patches.json` and only applies flags that are within range for your installed version.
</Note>

## The `-exp_spotify` Flag

<Warning>
  When `-exp_spotify` is passed, SpotX skips all `EnableExp` and `DisableExp` injections and defers entirely to Spotify's server-side experiment assignments. This means:

  - Premium upsell pop-ups (`enableInAppMessaging`) may reappear
  - Ad-like homepage sections may be shown based on your account's A/B bucket
  - Sidebar features may be enabled or disabled by Spotify without notice

  Use this flag only if you are troubleshooting a specific Spotify feature that SpotX's overrides are interfering with.
</Warning>

Even with `-exp_spotify`, the core `ForcedExp` injection script is still installed — it simply receives empty arrays, leaving `window.Spotx.RemoteExp` available for inspection but unmodified from Spotify's defaults.

## Debugging Experimental Flags

<Tip>
  Enable DevTools with `-devtools` and open the Spotify DevTools console. Type:

  ```javascript
  window.Spotx.RemoteExp
  ```

  This prints the full map of all resolved remote config values after SpotX has applied its overrides — useful for verifying which flags are active on your specific Spotify version.
</Tip>
